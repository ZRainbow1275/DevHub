> **填写时长**: 约 25–35 分钟
> **重要程度**:  公开发布的"软基础设施"。代码可以闭门造车，社区不能。

> **核心命题**: DevHub 公开发布后，要么"放出去自生自灭"，要么"主动经营社区"。本表帮助用户在项目零用户阶段就把"贡献流程 + 主题市场 + Skill 市场 + 商业化"四条线决策清楚，避免后期再改成本爆炸。

## 引言：社区与生态的因果关系

V1-Q-1.A.2 用户答 **C "公开发布"**。但 V1 未澄清：

1. **公开发布 ≠ 开源**（参考 Raycast：闭源免费 + 主题市场）
2. **开源 ≠ 接受贡献**（参考 SQLite：开源但 Public Domain，不接 PR）
3. **接受贡献 ≠ 有社区**（参考很多 GitHub 仓：1000 star 但 0 讨论）
4. **有社区 ≠ 有生态**（参考 VS Code：社区强，扩展生态强；vs Sublime Text：社区弱，生态早衰）

**Agent A 市场调研事实**:
- VS Code（GitHub Discussions + Issue templates + 月度 community sync）→ 强生态
- Linear（Slack 社区 + 月度 changelog）→ 中等生态
- Raycast（Slack + Extensions Store + 主题 Showcase）→ 强生态
- Notion（无开源 + Reddit 社区 + 模板市场）→ 弱开源 / 强模板生态
- Process Hacker（GitHub + Forum 老式）→ 弱社区

**用户已有线索**:
- V1-Q-7.K.4 Skill 市场用户选"后期"（推迟）
- V1-Q.K.2 用户答"否"AI 推荐主题
- V2-Q-23（可扩展性）将深化插件市场

**本表为 GitHub README / .github/ 模板 / docs/ 站点 / 商业化 landing 提供精确输入。**
