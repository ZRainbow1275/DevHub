## A. 注入失败诊断矩阵

### [Q-18.A.1] 失败模式枚举  锚定 [Must]

**背景**: 必须把所有可能的注入失败模式列清楚，每个失败模式有明确的诊断与处理。

**选项**（要识别的失败模式）:

| 失败模式 | 触发条件 | 诊断信号 | 处理动作 |
|---------|---------|---------|---------|
| 窗口不存在 | hwnd 失效 | IsWindow API = false | 重新查询窗口 / 报告任务失败 |
| 窗口已最小化 | 窗口在任务栏 | IsIconic = true | 自动 restore 后重试 |
| 窗口无焦点 | 用户切到其他窗口 | GetForegroundWindow != target | SetForegroundWindow + 重试 |
| 输入框未就绪 | 工具仍在初始化 | UIA 找不到 input element | 等待 + 重试 |
| 用户夺焦 | 注入中用户点击其他窗口 | 注入过程 GetForegroundWindow 变化 | 立即中止 + 提示 |
| 注入被忽略 | 工具未响应 | 注入后 input 内容未变 | 切换注入策略（剪贴板 vs 键盘）|
| 注入到错误位置 | 焦点在某 sub element | 验证后发现内容在错误的 input | 撤销 + 重新定位 |
| 编码异常 | 中文/Emoji/特殊字符 | 注入后字符乱码 | 切换 UTF-16 路径 |
| 速率限制 | 注入过快被限流 | 工具弹"too fast" | 退避后重试 |
| 工具崩溃 | 注入后工具退出 | process exit | Watchdog 介入（V2-§17）|
| 剪贴板冲突 | 用户同时复制其他内容 | 剪贴板内容不符预期 | 退化到键盘逐字符模式 |

**推荐默认**: 全部识别 + 全部分别处理

## C. CLI SHIM 协同

### [Q-18.C.1] 注入路径的优先级  锚定 [Must] 矛盾澄清

**矛盾事实**:
- V1-Q-6.D.2 用户选 F + E（GUI = SendInput + UIA / 终端 = pty）
- 用户备注："参照市面上的 AI CLI 的 inject 最佳实践，如果最佳实践和目前内容有冲突，作出深刻判断"

**当前事实**: WINDOW_SEND_KEYS 仅支持按键，**无文本注入** → 用户必须决策剪贴板路径

**市场最佳实践**:
- Claude Code: stdin 直接管道（推荐）
- Codex: stdin 管道
- Gemini: stdin 管道
- Cursor / Copilot: 仅 GUI，剪贴板 + Ctrl+V 最稳

**澄清选项**:
- A. **保持 V1 选 F + E**（SendInput + UIA + pty）
- B. **优先 SHIM stdin**（CLI 工具优先走 SHIM，不通过窗口注入）
- C. **B + 剪贴板兜底**（GUI 工具如 Cursor 用剪贴板 + Ctrl+V）
- D. **C + UIA 校验**（注入后用 UIA 验证内容确实进入了 input）
- E. **D + SendInput 兜底**（剪贴板被占用时退化到 SendInput）

**推荐默认**: E（最稳健，符合市场最佳实践）

**影响范围**: E 需新增 SHIM + ClipboardManager + UIAVerifier 三个模块
