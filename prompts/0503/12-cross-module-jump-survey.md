# 12 — 跨模块跳转与全局对象寻址协议需求表

> **填写时长**: 约 35–50 分钟
> **重要程度**: 应填，影响所有模块的相互引用与导航闭环
> **依赖**: 完成 V1-§02/04/05/06/08 + V2-§13/§14
> **核心命题**: 进程 / 端口 / 窗口 / AI 任务四大对象之间必须建立**全局唯一寻址 + 上下文菜单 + 状态共享 + 历史栈 + 收藏**，否则用户在多模块间跳转会丢失上下文

---

## 引言：跨模块跳转为何必须独立成表

**Agent B 源码事实**:
- ProcessDetailPanel.tsx 行 674-733 "关联" Tab 已展示端口/子进程/窗口列表，但**无法点击直接跳到对应模块**（仅文字）
- PortFocusPanel.tsx 行 534 已嵌入 AttachedGraphView，但点击节点后**不能跳转到该节点的所属模块详情页**
- WindowView.tsx 中按 PID 关联进程 / 按 owner 关联窗口的入口缺失
- TopologyView.tsx 已实现，但点击节点后无"跳到详情"按钮
- 缺统一对象寻址协议（无 URI / Deep Link 概念）

**用户场景**:
1. 用户在 process 卡片看到 PID 8812 占了 80% CPU → 想看它监听了哪些端口 → 应一键跳转到 port 模块并自动选中相关端口
2. 用户在端口列表看到 0.0.0.0:3000 异常 → 想看是哪个进程的哪个窗口 → 应能跳到 process 详情 + window 详情
3. 用户在 AI 任务详情中想看该任务关联的所有进程/端口/窗口 → 跨模块导航
4. 用户对几个 AI 实例做对比 → 需要并排查看 → 跨视图状态保持

**当前痛点**:
- 跳转 = 重新搜索（用户每次都要手动找 PID/port/hwnd）
- 选中态丢失（切到另一模块后选中态消失）
- 无前进/后退（误操作后无法 undo 视图）
- 无收藏（常用对象每次都要重新定位）

本表把跨模块导航的隐性失败链拆为 10 节，每节给出可量化、可验收的 Question。

## A. 全局对象寻址协议（Global URI / Deep Link）

### [Q-12.A.1] 是否引入统一寻址 URI  锚定 [Must]

**背景**: 类似浏览器的 `https://` URL，DevHub 内部对象需要统一标识符。无 URI = 跳转代码遍地 hardcode。

**选项**:
- A. **不引入**（直接传 PID / port / hwnd 作参数）
- B. **引入 URI 但仅内部用**（`devhub://process/8812`）
- C. **B + 用户可见**（命令面板 / 地址栏可输入 URI）
- D. **C + 外部可粘贴**（其他应用的人可粘贴 `devhub://` 链接到 DevHub 直达）
- E. **D + 协议注册**（注册 OS 协议处理器，浏览器点击 `devhub://` 直接打开 DevHub）

**推荐默认**: D（用户可见但不强制注册 OS 协议）

**影响范围**: D 需新增 ObjectURIService + 全局路由器 + 命令面板地址栏支持

### [Q-12.A.2] URI Schema 的命名空间设计  锚定 [Must]

**背景**: 设计一致的命名空间避免后续扩展时混乱。

**选项**:

```
A.  devhub://process/8812

```
C.  /process/8812

  （仅路径，类 React Router 风格，URI 但无 scheme）

```
D.  A + 多端兼容
  devhub://process/8812?host=local
  devhub://process/8812?host=remote-1（未来支持远程监控）
```

### [Q-12.A.3] URI 的稳定性保证  锚定 [Must]

**背景**: PID 在 OS 重启后会复用，hwnd 在窗口关闭后会失效。URI 必须有"重启后仍能寻址"的策略。

**选项**:

| 对象 | 易变 ID | 稳定 ID 方案 |
|------|--------|-------------|
| process | PID（重启失效） | A. EXE 路径 + cwd + 启动顺序 / B. cmdline hash / C. 用户 alias |
| port | port 号（重启可能换 PID） | A. port + protocol（足够稳定）/ B. port + listening process EXE |
| window | hwnd（窗口关闭失效） | A. (exe, title pattern, cwd) 三元组 / B. + 用户 alias |
| ai-task | UUID（DevHub 控制，永久稳定） | 直接 UUID 即可 |
| csv-batch | batch ID + CSV 文件 hash | |

**选项**:
- A. **URI 仅含易变 ID**（重启后失效 = 寻址失败）
- B. **URI 含易变 ID + 稳定标识 fallback**（`devhub://process/8812?fallback=exe:codex.exe,cwd:/repo/myapp`）
- C. **B + 自动迁移**（重启后系统自动把旧 PID 映射到新 PID）
- D. **C + 用户提示**（无法迁移时提示"该对象已不存在"）

**推荐默认**: D

**用户回答**: _____________________

## B. 跨模块上下文菜单标准

### [Q-12.B.1] 上下文菜单的"标准动作集"  锚定 [Must]

**背景**: 用户在任意对象（卡片 / 列表行 / 图节点 / 状态栏徽章）右键时应弹出统一的上下文菜单结构。

**当前**: ProcessDetailPanel/PortFocusPanel/WindowView 的右键菜单各自独立、字段不一致。

**选项**（统一上下文菜单的标准动作组）:

```
组 1: 查看
- 查看详情（默认）
- 看关系图（拓扑/神经/流程，三选一展开）
- 看历史

组 2: 跳转
- 跳到 process 模块（如对象有 PID 关联）
- 跳到 port 模块（如对象监听端口）
- 跳到 window 模块（如对象有窗口）
- 跳到 ai-task 模块（如对象属于某 AI 任务）
- 跳到 project 模块（如对象有 cwd 推断的项目）

组 3: 操作
- focus / kill / restart（按对象类型）
- inject text（如对象是 AI 窗口）
- 复制 URI
- 复制 PID/port/hwnd

组 4: 收藏
- 加入收藏夹
- 加入快捷栏
- 标记为"重要"

组 5: 多选 / 比较
- 添加到对比
- 选择更多同类对象（"选所有 codex.exe"）

组 6: 调试
- 导出诊断包
- 加入审计追踪
```

**推荐默认**: 全部 6 组
