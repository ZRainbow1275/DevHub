# 27 — 彩蛋与隐藏快捷键需求表（Easter Eggs & Hidden Shortcuts）

> **填写时长**: 约 15–25 分钟
> **重要程度**:  低（不影响主功能交付），但提升产品调性 + 用户口碑传播
> **依赖**: 完成 V1-§02（全局体验） + V2-§13（UX 可信度） + V2-§22（用户旅程）
> **核心命题**: 隐藏功能 / 彩蛋是"开发者送给用户的礼物"。但必须有节制（避免影响主流程） + 可发现（避免永远埋没） + 可关闭（避免成为干扰）。

---

## 引言：彩蛋的边界

彩蛋容易做过度，常见的两个反面教材：

1. **过度搞笑**: VS Code 早期 Unicode 字符 bug 显示 "Tabs vs Spaces"，被认为不够专业
2. **永远埋没**: 很多 App 的 Konami Code 彩蛋从未被任何用户触发

**Agent A 市场调研事实**:
- VS Code: 帮助菜单"切换屏幕方向" + 命令面板"Hello World" + Status Bar 隐藏 emoji
- IntelliJ: Live Template 隐藏快捷 + 帮助菜单 "Find Action..." 隐藏命令
- Notion: `/giphy` 隐藏命令 + Cover image 抽卡
- Linear: 主题切换的 Konami Code 触发"Halloween"
- Raycast: 隐藏 `quit` 命令 + 节日主题自动启用

**本表帮助用户决定**:
- 哪些彩蛋值得做（与 DevHub 调性一致）
- 哪些只是"花架子"
- 是否做"用户成就系统"（最大的彩蛋类）
