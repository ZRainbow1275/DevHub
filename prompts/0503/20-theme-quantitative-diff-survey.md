# 20 — 主题量化差异表（联动机制 + 6 维 px/ms/density 量化 + Theme Editor）

> **填写时长**: 约 35–50 分钟
> **重要程度**: ⭐⭐⭐⭐⭐ 用户原话"主题切换依然都只算是换了个颜色，而没有从布局、组件表现等各类情况给出不同的表现"——本表是终结这条隐疾的核心
> **依赖**: 完成 V1-§03 + V2-§13
> **核心命题**: 把"切主题=换色"升级为"切主题=换 6 维联动 + 视觉跨度极大 + 渐进过渡可见"，每对主题的差异必须可量化（px/ms/density）、可验收、可分享

---

## 引言：为何用户说"只换了颜色"

**Agent B 源码事实**（来自 `refs/source-snapshot-v2.md` 维度 6）:

- `src/renderer/theme/theme-language.ts` 行 80-81 仅定义 `radiusFamily / motionLevel` 默认关联
- 推断: **密度（density）、圆角（radiusFamily）、动效（motionLevel）切换色系（palette）时无自动协调**
- UX 缺陷: 切换 palette 时应自动推荐其他 3 维，但**当前逻辑仅在 THEME_PRESETS 定义，不在切换时触发**

**Modern-Light vs Constructivism 当前实测差异**（同源码报告）:

| 维度  | Modern-Light（推断）  | Constructivism（实测） | 量化差距 |
| ---------- | -------------------- | -------------------- | ------- |
| 边框宽度  | 1px  | 2px solid  | 1px  |
| 阴影形态  | 柔和 elevation  | 3px 3px 0 硬偏移  | 形态完全不同 |
| 圆角  | 8px 推断  | 0 / 2px  | 6px–8px |
| 动效时长  | 150ms balanced  | 150ms balanced  | **0**（这就是为什么用户感觉"没变"）|
| 字体  | Inter  | Oswald / Bebas Neue  | 字族不同但**默认仅切色**|
| 间距基数  | 未定义  | --spacing-base: 4px  | 1 个变量级别 |

**结论**: 切换 palette 时，density / radius / motion / typography / decoration / spacing 这 5 维**没有跟上**。

**本表的目标**:

1. **A 节**: 强制 4 维及未来 6 维**自动联动**（切色系 → 其他维度自动跳到该主题的预设值）
2. **B 节**: 每对主题的**6 维差异表**——必须填具体数值（px/ms/density 倍率/elevation 等级/字号 px/字族名）
3. **C 节**: 每个主题对应的**市面参考产品截图链接**（让用户能"看到"该主题应该长什么样）
4. **D–K 节**: 渐进过渡时序、Theme Editor 可视化、Theme Pack 预设组合、JSON 分享格式、组件级独立尺寸覆盖、持久化粒度、A11y 协调

**与 V1-§03 的差异**: V1 仅问"是否扩展为 6 维"（用户已选 B+C+E），但**没问每对主题在每维的具体数值**——本表补这一空缺。

## A. 4 维 / 6 维的"自动联动"机制（修复"只换色"的根因）

### [Q-20.A.1] 切换 palette 时其他 3 维（density / radius / motion）的联动行为  锚定 [Must] 矛盾澄清

**背景**: V1-Q-3.A.3 用户已"采纳默认"——即每个主题有期望的"特征向量"。但 source-snapshot-v2.md 行 130-132 证实：当前代码切色时其他维度未自动跳。

**选项**:

- A. **完全独立**（切 palette 不动其他 3 维，用户必须手动调）— **当前现状**
- B. **强联动**（切 palette → 其他 3 维**自动**跳到该主题的预设值，用户不可单维微调）
- C. **软联动 + 弹提示**（切 palette → 弹"建议同时把密度切到 X、圆角切到 Y、动效切到 Z，是否应用"）
- D. **软联动 + 静默应用 + 可撤销**（切 palette → 自动应用 + 顶部出现"已联动应用 3 维变化（撤销）"小提示，6s 后消失）
- E. **D + 用户可锁定某维**（用户在设置里勾"密度由我控制，不要随主题变"）

**推荐默认**: E（最优体验：既解决"只换色"又给定制化用户留口子）

**影响范围**: theme-language.ts 必须新增 `applyPresetCoordination(palette)` 函数；useTheme.ts 切换流程必须改

### [Q-20.A.2] 联动应用的"过渡顺序"  锚定 [Must]

**背景**: 一次性切 4–6 维若同时变会导致"画面闪烁"。需要分序。

**选项**（建议的过渡顺序，单位 ms）:

- A. **同时切**（0ms 内全部变）
- B. **颜色先 → 圆角 → 字体 → 阴影 → 动效 → 装饰**（每段 100ms，共 600ms）
- C. **颜色先（150ms）→ 圆角 + 阴影并行（150ms）→ 字体（200ms）→ 装饰（150ms）= 共 650ms**
- D. **C + view-transition API 包裹**（浏览器原生过渡）
- E. **用户可选 A / B / C / D**

**推荐默认**: D（V1-Q-3.A.4 用户已选 D = view-transition）
