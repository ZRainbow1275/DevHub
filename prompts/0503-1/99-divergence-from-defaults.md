## B. 改写归因（Why 用户改这些）

### B.1 隐私零容忍（#15、#16）
**根因**: 「不连接云端，一切走本地」（09.J.3）
**Spec 影响**: 所有"是否需要联网"的设计必须给出**本地等效方案**

### B.2 冗余开发优先（#5、#6、#10、#13、#23-24）
**根因**: 用户反复强调「冗余开发」「宁多毋少」
**Spec 影响**: 默认勾选所有可选项，性能预算后置（先全做再优化）

### B.3 多实例 + 长任务的稳定性（#12、#22）
**根因**: AI 任务编排涉及 4-6 个 Claude Code 同时跑 + 24/7 运行
**Spec 影响**: hwnd 不可信 → 启动顺序索引 + 三元组 + alias 四维 key

### B.4 不重构哲学（#1、#19）
**根因**: 「不需要出现大的重构」
**Spec 影响**: IA 三栏不动 + 核心模块保留自研，集成在外围

### B.5 主题差异化（#2、#3、#4）
**根因**: 「切主题只换颜色，需要从布局/组件给出不同表现」
**Spec 影响**: 4 维主题轴（palette × density × radiusFamily × motionLevel）+ 主题独立音色 + 苏维埃禁暗

### B.6 拓扑既附属又顶级（#23、#20）
**根因**: 用户希望拓扑既是详情面板的附属（精确）又是顶级入口（全局视野）
**Spec 影响**: 双入口设计 — ActivityBar 增加 Topology Global Tab + 三大模块详情内 E 模式

### B.7 安全谨慎（#17）
**根因**: taskkill 滥用风险大
**Spec 影响**: 封装层强制 PID 校验，禁止批量

### B.8 用户自定义偏好（#7、#8）
**根因**: 用户喜欢自定义规则
**Spec 影响**: 分组规则 / 排序规则 / 主题预设 / 命令面板都需"用户可保存"

### B.9 不限制 AI 产出（#21、#22）
**根因**: 「时间成本不是问题」「交给 AI 写的」
**Spec 影响**: 不压缩 Spec 数量，但每份必须满足 13 章节质量门

### B.10 验收红线（#25）
**根因**: 7 轮反馈"AI 探测不准"
**Spec 影响**: AI 探测准确性必须有 P0 级 E2E 测试，且 R8.A 用户感知断言必含

## C. PRD 编撰检查清单

每份 Spec 起草时，必须自问：

- [ ] 我是否在该 Spec 中应用了上述 25 条改写？
- [ ] 我是否在 Spec "动机"章节引用了用户原话？
- [ ] 我是否标注了哪些字段/选项是"用户改写默认"（CHANGE 标记）？
- [ ] 我是否避免了与"隐私零容忍"冲突的设计？
- [ ] 我是否给出了 R8 三大新约束的对齐说明？
- [ ] 我是否考虑了 24/7 长跑下的稳定性？
- [ ] 我是否考虑了 4-6 实例并发？
- [ ] 我是否设计了用户感知断言（与 11.G.2 五条对齐）？

## D. 与"R8 三大新约束"的对齐

| 约束 | 与改写决策的关系 |
|------|----------------|
| **不重构大框架** | 直接对应 #1（IA 三栏不动）、#19（核心模块自研） |
| **冗余开发优先** | 对应 #5、#6、#10、#13、#23-24（全选/冗余入口） |
| **集成而非自研** | 对应 #19（集成为主，核心保留自研） |

→ 三大新约束并不矛盾：「不重构」=保护现有架构，「冗余开发」=丰富用户面，「集成」=外围用库

## E. 高风险改写（PRD 必须额外评审）

### E.1 #5（进程字段全集）
**风险**: 字段获取性能 + UAC 提权次数
**缓解**: D（按需取重字段 + 24h 提权记忆）

### E.2 #15-16（零遥测）
**风险**: 调试困难、无法量化用户痛点
**缓解**: 本地 OpenTelemetry 完整收集 + 诊断包导出

### E.3 #18（OCR 不集成）
**风险**: AI 信号融合少一个维度
**缓解**: 接口预留 + 文档明确 R9 启用条件

### E.4 #20（顶级拓扑 + 编排编辑器）
**风险**: R8 工作量增加
**缓解**: 用户已确认「时间不是问题」+ 「不限 Spec 数」

### E.5 #22（不限周数）
**风险**: 滚动延期失去验收节奏
**缓解**: 6 条质量门触发即回滚（11.D.1 全选）

## F. 总结

**用户的偏好画像**:
1. **隐私至上** — 零遥测，本地优先
2. **功能极致** — 冗余开发，宁多毋少
3. **稳定第一** — 多维 key + 长任务支持
4. **保留架构** — 不重构，集成为辅
5. **时间无关** — 质量优先于速度
6. **用户自定义** — 一切可保存可切换
7. **验收红线** — AI 准确率 + 5 条感知断言不可妥协

→ PRD/Spec 编撰阶段必须以这张画像为锚，每个设计决策都要回答"是否符合用户画像"。
