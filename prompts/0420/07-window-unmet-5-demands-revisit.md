**验收契约（必须写死，不再用模糊描述）：**

### P4.2-b AI 任务感测准确性（多实例识别）

**用户原话：**
> "窗口对于ai工具是否完成任务的感测还是太愚钝太无效，经常出现误报、瞎报、错报的问题"

**历史反馈次数：6 次**

**根因讨论（沿用 R4 `prompts/0413/02-terminal-signal-fusion.md` + `07-aitask-confidence-state.md`）：**
- 单信号（进程 CPU 降低 或 窗口标题变化 或 stdout 停止）都不足以判定"任务完成"
- 必须做**多信号融合**：
  - 工具特定终端文案（如 Claude 的 "Stopped" marker）
  - CPU 稳定低于阈值 N 秒
  - 光标/输入可用状态（如有 accessibility API）
  - 连接 stdin 空闲 M 秒
- 需要**置信度状态机**：idle → thinking → coding → waiting-input → completed，每个状态有进入/保持/退出条件

**验收契约：**
- [ ] 感测状态机 5 个状态可在"开发者观测栏"实时查看
- [ ] 误报率：连续 30 分钟运行 2 个并发实例，误报 ≤ 1 次
- [ ] 漏报率：明确触发完成的 10 次中，漏报 = 0
- [ ] 迟报：完成到通知 < 5s

**R5 落地情况：**`v2-backend-core` archive 时改了 `AITaskTracker.ts / ToolMonitor.ts`，但用户仍报误报/漏报/迟报三同时。可能仍是单信号检测，或状态机漏写了退出条件。

## 共通：为什么 R5 修了却没生效

R5 修复批次在命名上覆盖了这 5 个诉求，但用户感知仍是"完全没有实现"。元根因可能是：

1. **UI 做了但后端没接** — 组件/按钮存在，点击后 IPC 通道缺失或处理器未注册
2. **后端做了但 UI 没接** — IPC 处理器存在但 renderer 未订阅或 selector 写错
3. **双向都做了但状态污染** — `aliasStore`/`windowStore` 存取 key 不一致，读不到
4. **测试只覆盖单实例** — 单个 AI 窗口能跑通，多实例场景崩溃
5. **持久化错配** — 应用重启后别名丢失，用户判定"没实现"

**R6 之后的修复必须同时提供**：
- 主进程侧每个 IPC 通道的 handler 存在性 + schema 单元测试
- 渲染侧 store → 组件的端到端 React Testing Library 测试
- Playwright E2E：多实例命名 → 通知 → 持久化恢复
