# P6.1 — 拓扑图无法正常显示 [P1]

> Round: R6 · 2026-04-20
> 用户原话：**"拓扑无法正常显示，如图"**
> 截图：`屏幕截图 2026-04-15 195547.png`

---

## 一、症状

截图可见：
- 顶部统计：进程 334 / 端口 126 / 窗口 9 / 项目 0
- 主区左上角有一个唯一实心渲染的节点（`node.exe`，两层同心圆 + 淡黄色光环）
- 其他节点**全部退化为虚线多边形的轮廓**，占满右下大片区域，相互无语义联系
- 左下角有完整的图例（项目 / 进程 / 端口 LISTENING / ESTABLISHED / TIME_WAIT / 窗口 / 外部连接）

推测是力导向布局未完成 / 节点集合错配 / 边集合渲染成 path 但无关联节点。

## 二、根因假设

1. **数据规模过大**：334 进程 + 126 端口 + 9 窗口 → 约 469 节点和更多边。xyflow / d3-force 未做分层或聚合，导致布局不收敛
2. **边渲染与节点位置错位** — 边的 source/target 引用的节点 id 在节点集合中不存在，xyflow 按 fallback 位置（0,0 附近）绘制
3. **强制布局未等待完成** — 组件立即渲染 node/edge，d3-force tick 还没跑完
4. **节点样式错误** — 大部分节点被应用了 `fill: none; stroke-dasharray: 4`，看起来像虚线

## 三、验收契约

**前置**：先完成 P6.2（拓扑附属化设计校准）。如果最终方案是"点选对象才显示局部图"，则数据规模会从 469 节点降到单位数 ~ 数十节点，当前渲染 bug 自然缓解。

如果方案 A（详情 Tab 内显示局部图）：
- [ ] 单对象中心的图节点数 ≤ 50（包含 1-2 hop 展开）
- [ ] xyflow 布局在 500ms 内稳定
- [ ] 节点样式按类型区分（进程/端口/窗口/外部连接）
- [ ] 边必须与节点双向关联，无孤立边
- [ ] 图例保留，但合并到图右上角 popover

## 四、关联

- **必须与 `11-topology-flow-scope-violation.md` 一起处理**
- 依赖 P2.1 Runtime 修复（如果拓扑每次扫描都重建，仍会造成 CPU 爆）
