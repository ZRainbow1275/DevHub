# C1 — 【需求校准】拓扑图 / 流程图 应为进程/端口/窗口的"附属功能"

> 日期: 2026-04-15
> 严重性: **P0-Design**（不是 Bug，是根本性需求澄清；影响整条拓扑线的实现路径）
> 首次明确澄清: R5（R1 PRD §2.5 + §2.7 的定位偏离）
> 证据: Image #7（拓扑异常）+ Image #8（流程图异常）+ 用户原话

---

## 一、用户原话（精确引用）

> **拓扑原本的功能设计，拓扑是基于「进程」、「端口」、「窗口」三大板块的附属功能。**
> **旨在完成：点击某一进程、端口、窗口后，可以通过直观的拓扑图定点定向查询该单一选中对象的联系。**
> **但现在该功能被单独拎出做，是不符合我的要求的。**
>
> 流程图同上。

---

## 二、当前错误实现（R5 观察）

从 Image #7 / Image #8 + 用户截图的顶部导航可见，**当前 DevHub 把"拓扑"和"流程图"做成了与「进程 / 端口 / 窗口 / AI 任务」并列的**顶级 Tab**：

```
系统监控 > [进程] [端口] [窗口] [AI任务] [拓扑] [流程图]
                                          ↑      ↑
                                          错误的顶级独立化
```

表现出两个连带问题：
- **Image #7 拓扑**：全局铺 300+ 进程 / 100+ 端口 / 9 个窗口 = 四百节点的全景图，节点挤在左上角，布局失败
- **Image #8 流程图**：同样是全局视图，右下出现异常色块（可能 minimap 渲染错误）

## 三、用户真正想要的设计（重建信息架构）

```
系统监控 > [进程] [端口] [窗口] [AI任务]
              │       │       │       │
              ├─ 点击 PID / 端口 / 窗口 → 右侧 / 弹出层 / 下方面板
              │
              ▼
  该单一对象为中心的局部关系图
  (动态、聚焦、直观)
  ┌────────────────────────┐
  │  选中节点               │
  │   ├── 关联进程          │
  │   ├── 关联端口          │
  │   ├── 关联窗口          │
  │   └── 外部连接（如网络）│
  └────────────────────────┘
```

**对比 R1 PRD §2.5（进程神经流线图）的校准**：
- R1 PRD 预期"进程关系图改为动态关系流线图"——但未明说是全局还是聚焦局部
- **R5 校准**：永远**不做全局拓扑**；永远以**单个选中对象为根**，展开**1~2 跳邻接关系**

**对比 R1 PRD §2.7（端口拓扑完善）的校准**：
- R1 PRD 已提"支持聚焦到单个端口"——方向对，但 R5 明确"**这就是唯一正确的视图**，没有全局视图这回事"

---

## 四、重设计方案骨架

### 4.1 信息架构（IA）
- **删除**顶级 Tab 里的"拓扑"和"流程图"入口
- **移植**拓扑能力为"附属面板"：
  - 进程 Tab 里点 PID → 详情面板新增 `关系图` Tab（当前是"基础/资源/网络/环境/模块"，再加一个）
  - 端口 Tab 里点端口 → 右侧侧栏 `关系图` section
  - 窗口 Tab 里点窗口 → 弹层 `关系图`

### 4.2 可视化策略
- 以选中对象为**圆心**，最多 2 层邻接节点（避免画 400 节点）
- 节点类型：
  - 中心：选中对象（进程/端口/窗口之一）
  - 第 1 层：直接关联（进程→监听端口, 端口→占用进程, 窗口→所属进程）
  - 第 2 层：间接关联（进程的父进程 / 子进程, 端口的远程连接, 窗口的兄弟窗口）
- 动态流线（参考 R1 PRD §2.5 "神经流线图"）：保留但**限定在小范围**才有性能预算

### 4.3 流程图 vs 拓扑图差异化
- **拓扑图**：静态关系（谁连谁，层级），右侧详情里
- **流程图**：动态调用 / 时序（谁先启动谁、谁 spawn 了谁、谁的 stdout 流向谁），时间轴驱动
- 都以选中对象为起点，不做全局视图

### 4.4 代码层面的迁移
- 目前独立 Tab 的"拓扑"/"流程图"组件：
  - 保留其渲染核心（React Flow / d3 / xyflow）
  - 移除"加载全部进程/端口/窗口"的入口
  - 改为接受 `{ rootId, rootType }` props，只渲染以该节点为根的子图
- 路由 / Tab 结构删减

## 五、这个需求校准会推翻 / 改写哪些已有工作

| 旧文档 / 代码 | 影响 |
|---------------|------|
| R1 PRD §2.5 进程神经流线图 | 保留愿景，但**仅**用于单进程聚焦图（不做 400 节点全图） |
| R1 PRD §2.7 端口拓扑完善 | 已提"聚焦单端口"，继续保持，去掉任何"全局端口拓扑"的 scope |
| R3/R4 spec 里涉及顶级拓扑的 routing | 需删除 / 改写 |
| 当前代码 `src/renderer/components/monitor/` 中的独立 Topology/FlowView | 保留核心引擎，移除顶级入口，重新绑定到"附属面板" slot |
| Image #7/#8 所见的全局渲染 | 直接废弃该数据流 |

## 六、下一步决策点（交给下一个对话 + 用户讨论）

1. **确认** IA 调整（删顶级 Tab）是否会影响已有快捷键 / 布局配置？
2. **确认** "附属面板" 的承载形式：
   - Option A: 详情 Panel 里再加一个 Tab
   - Option B: 独立弹层 / 抽屉
   - Option C: 悬浮气泡图（hover 预览 + 点击钉住）
3. **确认** 聚焦图的可视化引擎是否沿用 React Flow / xyflow，还是换 d3-force（神经流线需要力导）
4. **确认** 默认邻接深度（1 层 / 2 层）是否可用户调整

## 七、验收标准

- 顶级 Tab 里**不再出现**"拓扑"和"流程图"独立入口
- 进程 / 端口 / 窗口**每个**详情视图里都有清晰的"关系图"子面板
- 点击任一对象都能在 < 500ms 内显示以该对象为中心的聚焦关系图
- 关系图里节点 ≤ 20 个（1 层）/ ≤ 60 个（2 层），不出现 400 节点挤压的情况
