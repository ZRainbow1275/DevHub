# R8.B spec-16 Accessibility Foundation

## Implementation Status

This slice adds and verifies the R8.B accessibility foundation for DevHub without claiming a manual full-app WCAG usability audit.

- Source spec: `prompts/0503-2/R8.B/spec-16-a11y-full.md`
- Feature flag: `R8.B.a11y.full`
- Status: verified for R8.B spec-16 automated/live critical axe, keyboard foundation, component ARIA audit, and benchmark gates
- No mock boundary: main-process self-check does not fabricate axe results; the axe script requires a live renderer URL.

## Dependencies

- `axe-core`
- `@axe-core/playwright`

Both dependencies are installed in `devhub/package.json` and locked through `pnpm-lock.yaml`.

## Contracts

Accessibility contracts live in `src/shared/schemas/r8-runtime.ts`:

- `A11yPrefs`
- `A11yOsPrefs`
- `A11yAxeViolation`
- `A11yContrastFailure`
- `A11ySelfCheckResult`

Shared accessibility constants live in `src/shared/a11y.ts`:

- WCAG contrast limits
- announcement dedupe limits
- focus-ring thickness values
- axe impact values

## Main Process

- `src/main/services/A11ySelfCheck.ts`
  - Persists user preferences in `electron-store` under `devhub-a11y`.
  - Reads real OS accessibility preferences through Electron `systemPreferences.getAnimationSettings()` and `nativeTheme.shouldUseHighContrastColors`.
  - Returns a truthful limited self-check result with `axeExecuted=false` until an external live-renderer axe run is performed.

- `src/main/ipc/a11yHandlers.ts`
  - `a11y:get-prefs`
  - `a11y:set-prefs`
  - `a11y:os-prefs`
  - `a11y:run-self-check`

- `src/main/ipc/index.ts`
  - Registers and cleans up the a11y handlers with the extended handler set.

## Axe Audit

- `scripts/a11y-audit.mjs`
  - Requires `--url` to a live renderer page.
  - Runs Playwright Chromium with `@axe-core/playwright`.
  - Uses WCAG A/AA tags.
  - Fails by default on `critical` violations.
  - Can write JSON output with `--output`.

Usage:

```bash
pnpm -C devhub a11y:audit -- --url http://127.0.0.1:5173 --output reports/a11y.json
```

The script intentionally exits with code `2` when `--url` is omitted because offline runs cannot provide real axe evidence.

## Component ARIA Audit

- `scripts/a11y-component-audit.mjs`
  - Scans production renderer TSX source without using mocked DOM or fabricated axe results.
  - Audits the current custom focusable/control surfaces: separators, custom button cards, switches, focusable scroll regions, SVG treemap tiles, inline SVG treemap markup, roving tabindex groups, command palette dialog semantics, and live regions.
  - Fails when a registered ARIA surface loses required role, label, state, or keyboard semantics.
  - Current run: 169 renderer TSX files scanned, 7 production `tabIndex={0}` entries, 10 audited ARIA surfaces, 0 blocking findings.

Usage:

```bash
pnpm -C devhub a11y:component-audit
```

Report:

- `docs/r8/a11y-component-audit.md`

## Axe Benchmark

- `scripts/bench-a11y-axe.mjs`
  - Requires a built `out/main/index.js` and launches the real Electron app through Playwright.
  - Injects real `axe-core` into the Electron renderer and scans five live surfaces: `home-main-shell`, `monitor-process-surface`, `dashboard-route`, `settings-dialog`, and `command-palette`.
  - Fails when any surface is missing, any critical violation is found, or any surface exceeds the default `1500ms` axe-run budget.
  - Latest verified run: `criticalViolationCount=0`, `missingSurfaces=[]`, `durationStats.p95=532.5ms`, `budgetMs=1500`, `passed=true`.

Usage:

```bash
pnpm -C devhub bench:a11y
```

- The 2026-05-16 closure fixed additional live multi-surface critical findings: statusbar fallback duplicate registration interrupting `a11y:*` handler startup, anonymous `ProcessFilterBar` clear-sort button, anonymous `SettingsDialog` icon-only buttons, and cmdk outer listbox ownership.

## Scope Boundaries

- `A11ySelfCheck` remains a limited local check and reports `axeExecuted=false` by design; live axe evidence comes from the real Electron E2E and `bench:a11y`.
- The R8.B spec-16 automated/live critical axe gates are closed for the verified high-value surfaces; this does not replace manual assistive-technology testing or a full human WCAG audit for every future route.
- CI still uses the Windows single-grep Electron smoke path for `R8.B spec-16`; the standalone live-URL `a11y:audit -- --url ...` script remains available for manual/runtime URL audits.
